# 架构与演示

## 三分钟演示

1. 新建两篇文档，给出不同的标题和正文；输入标题、表格和任务列表，查看实时预览。
2. 快速输入后切换另一篇，再回到第一篇，说明防抖保存为何不会把内容写错。
3. 刷新页面，确认正文与当前选择恢复。
4. 搜索正文，重命名文档；展示删除确认与空列表状态。
5. 导出一篇 Markdown，再导入；备份全部 JSON，再恢复，说明恢复会保留原文档并生成新 ID。
6. 在另一个标签页编辑，展示冲突提示；导出当前内容，再刷新读取最新数据。

## 数据流

```mermaid
flowchart LR
  A[输入框 onChange] --> B[store.edit 文档ID与正文]
  B --> C[内存快照更新]
  C --> D[订阅通知 React]
  D --> E[编辑区与 Markdown 预览]
  C --> F[500ms 防抖调度]
  F --> G[localStorage]
  G --> H[刷新时验证并恢复]
```

`App.tsx` 负责交互与布局，`store.ts` 负责模型、调度与存储，`Preview.tsx` 负责 Markdown 渲染。UI 通过 `useSyncExternalStore` 订阅不可变快照，便于单独测试数据逻辑。

## 为什么按 ID 管理文档

名称可以修改，也可能重复；随机 ID 才代表文档身份。编辑时传递 ID，导入备份时生成新 ID，防止覆盖原文档。

## 保存策略

正文先进入内存，停顿 500 ms 后写入当前完整快照。连续输入会重置定时器；切换、新建、页面隐藏或离开前调用 flush。写入失败保留内存，并给出导出/重试入口。

选用整个文档集合的快照让读写和恢复逻辑简单，代价是每次保存序列化全部文档，不适合海量文档。大规模版本可考虑 IndexedDB 的逐文档事务；本项目没有做相关性能宣称。

## 异常与边界

- 本地数据先验证版本、字段和 ID；无法读取或格式损坏时暂停写入，不自动覆盖原始数据。
- 多标签页监听 storage 事件，冲突时保留本页内容，暂停保存，提示导出并刷新；当前不自动合并。
- Markdown 文件限制 1 MB，校验扩展名、UTF-8 和非文本字符；JSON 备份最大 10 MB。
- 文件名在导出前处理不安全字符。备份恢复采用追加副本，而不是清空和覆盖。
- 页面显示纯文本/安全的 Markdown，禁用原始 HTML，限制链接协议，外部图片不自动请求。
- 浏览器数据按源隔离，更换浏览器、域名或端口不会自动同步。

## 测试如何证明行为

| 风险 | 验证 |
| --- | --- |
| 连续输入频繁写盘 | 模拟计时器，断言只保存最终内容 |
| 切换后内容写错 | 两篇文档不同内容，切换并重新创建 store 验证 |
| 存储写入失败 | 模拟抛错，断言内存不丢失且重试成功 |
| 数据损坏被覆盖 | 输入非法 JSON / 版本，断言原始字符串不变 |
| 另一标签页覆盖 | 模拟外部变化，断言暂停保存 |
| 恢复备份覆盖原文档 | 断言数量增加，内容相同但 ID 不同 |
| 恶意 HTML / 链接 | 验证 DOM 无 script，危险链接无 href |
| 页面操作不连贯 | 模拟新建、编辑、搜索、重命名、删除和刷新 |

测试结果以 CI 徽章和仓库内测试文件为准。当前项目无服务器、账号系统、云同步，运行命令与在线演示地址见根目录 README。
