# 从零理解纸间

不要一次读完整个项目。先运行页面，每次只改一个地方，再观察结果。

## 1. 找到页面入口

先看 `frontend/index.html` 中的 `root`，再看 `frontend/src/main.tsx`。`createRoot` 把 React 页面放进这个 HTML 元素，`App` 是整个应用的入口组件。

练习：把浏览器标签页名称改成你喜欢的名字。标题在 `index.html` 的 `title` 标签中。

## 2. 看懂页面结构和样式

读 `App.tsx` 的 `return`：`aside` 是文档侧栏，`main` 是工作区，`textarea` 是输入框，`Preview` 是预览组件。花括号内可以放 JavaScript 表达式。

`style.css` 用类名控制颜色、间距和布局。媒体查询让窄屏上的两栏变成上下排列。

练习：找到 `.primary`，更改新建按钮颜色。

## 3. 理解数据驱动页面

`store.ts` 的 `Doc` 描述一篇文档：唯一 ID、标题、正文、更新时间。`docs` 是文档数组，`activeId` 决定当前显示哪一篇。文档 ID 与标题分开，因此重命名不影响文档身份。

`useSyncExternalStore` 订阅数据变化。用户在输入框打字时，`onChange` 调用 `store.edit`；存储对象更新状态并通知 React；编辑区和预览区收到相同正文。

练习：跟踪一次 `onChange → edit → change → emit → 页面更新`，用自己的话说明每一步。

## 4. 理解实时预览

`Preview.tsx` 使用 `react-markdown` 解析正文，`remark-gfm` 增加表格和任务列表。输入不是直接当成 HTML 插入页面，因此原始 HTML 被忽略，链接还会经过 `safeUrl` 检查。

练习：输入标题、加粗、表格和任务列表，观察它们的 HTML 表现。外部图片目前只显示占位信息。

## 5. 理解自动保存

页面状态在内存中，刷新后会消失；`localStorage` 用来跨刷新保存。数据写入前先用 `JSON.stringify` 转为字符串，读取后验证版本、字段和文档 ID。

防抖让每次输入取消上一个计时器，停下 500 ms 后再保存。切换、新建或关闭页面前调用 `flush`，立即写入最新快照。快照保存完整文档集合，避免旧文档的延迟任务写到新文档中。

练习：看 `store.test.ts` 中“快速切换文档”测试，理解为什么两篇内容不会混淆。

## 6. 学会处理异常

存储满了或浏览器禁用存储时，写入可能抛出异常。捕获异常后保留内存中的正文，提示用户导出或重试。数据损坏时停止写入，避免把原始数据覆盖掉。

另一个标签页修改同一份数据时会触发 `storage` 事件。当前页面暂停保存，用户可以先导出再刷新，这不是自动合并。

## 7. 看测试，再做小改动

先运行 `./project.sh test`。存储测试使用模拟计时器，不必实际等 500 ms；组件测试模拟新建、输入、搜索、重命名、删除等操作。修改功能后再次运行构建、测试和静态检查。

建议练习：添加“最后修改时间”显示，或者给空文档加入字数提示。完成一项后提交一次 Git，提交说明写清实际改变。

## 手工验收清单

- 新建两篇文档，快速切换输入不同文字，刷新后检查内容。
- 搜索标题或正文，取消搜索后确认所有文档仍存在。
- 重命名；取消删除；确认删除；删除最后一篇后再次新建。
- 导出 Markdown，再导入检查标题与正文。
- 备份全部 JSON，再恢复；原文档应保留，导入副本应有新的 ID。
- 在第二个标签页编辑，检查第一个标签页是否出现暂停保存提示。
- 将窗口变窄，检查编辑区、预览区及按钮是否可用。
